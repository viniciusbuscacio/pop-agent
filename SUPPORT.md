# Support

Pop Agent is a pre-1.0, self-hosted project maintained on a best-effort basis.
There is no guaranteed response time, uptime commitment, or support for modified
production deployments.

## Before asking for help

1. Confirm the problem on the latest tagged release.
2. Read the [README](README.md), [deployment guide](deploy/README.md), and
   [operations specification](docs/specs/Spec-Pop-Deployment-and-Operations.md).
3. Check existing issues and pull requests.
4. Collect the Pop Agent version or full commit, supported host/platform,
   deployment shape, and minimal reproduction using synthetic data.

Use the bug report form for reproducible defects. Use GitHub Discussions for
questions, setup help, and early ideas; use the feature request form once a
proposal has a focused outcome. Do not use public channels for private
deployment consulting or share logs before sanitizing them.

## Security and private data

Report vulnerabilities privately according to [SECURITY.md](SECURITY.md).
Never post credentials, recovery keys, session tokens, private conversations,
database contents, personal files, private hostnames, or unredacted logs.

The project cannot operate a contributor's server, provider account, DNS, TLS,
firewall, reverse proxy, tunnel, or host backup system. Those remain operator
responsibilities.
